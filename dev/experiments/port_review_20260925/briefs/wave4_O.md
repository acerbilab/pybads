## How PyBADS reaches this code at default options

Every run. Every search and every poll decides by `_eval_improvement_`: a success when the improvement of the new point over the incumbent exceeds the sufficient improvement (`tol_improvement` times the mesh size to the `forcing_exponent`, floored at `tol_fun` with `sloppy_improvement`, on by default), an incremental improvement when it is positive; the end of every iteration compares the incumbent with the iterate `tol_stall_iters` iterations back (the stall criterion), and the end of every failed poll with the iterate `accelerate_mesh_steps` back (the accelerated mesh reduction, on). At level 0 the SDs are 0 and the improvement is a difference; at levels 1 and 2 the values are GP estimates with SDs, and the improvement takes `improvement_quantile` (0.5). A noisy run ends by re-estimating its iterates and returning the one of lowest `fval + sqrt(2) erfcinv(2 final_quantile) fsd` (`final_quantile` 1e-3), skipping the first. The search ranks its candidates, and the poll its points, by `acq_fcn_lcb` with the default schedule of `sqrt_beta` (`search_acq_fcn` and `poll_acq_fcn` are `('acq_LCB', None)`). After each search `update_hedge` updates the gains of the two ES strategies (`hedge_gamma` 0.125, `hedge_beta`, `hedge_decay`), which set the probabilities of the next choice. After every refit `local_gp_fitting` recomputes `len_scale` (the length scales), `poll_scale` (the length scales, rescaled by `gp_rescale_poll` about their geometric mean and clipped) and `effective_radius` (from the kernel's shape `alpha`, `use_effective_radius` on); the training set of each rebuild keeps the neighbours within `gp_radius` (3) times `effective_radius`, in the distance of `udist` scaled by `len_scale`. Sto-BADS's rule runs only with `stobads` (off by default). Say for every finding whether a default run reaches it, at which uncertainty level (0 deterministic, 1 noise inferred, 2 `specify_target_noise`), and which option or input reaches it otherwise.
