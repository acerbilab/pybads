fix: the last search of a round adds no point to the GP, as in MATLAB BADS (W1-9)

The condition for adding the search point to the GP in _search_step_, u_search.size > 0 & self.search_es_hedge.count < search_n_try, parsed as u_search.size > (0 & count) < search_n_try and was always true, so every search added its point; written with `and`, it would have counted the hedge's searches over the whole run and stopped adding after the first search_n_try of them. MATLAB BADS tests the round's counter (bads.m:633, optimState.searchcount < options.SearchNtry), which it increments before the search (bads.m:542), as _search_step_ does, so the last search of a round leaves its point out. The condition now reads optim_state["search_count"], with `and`, and AGENTS.md's "MATLAB logicals" names it as a slip that was. It moves nothing: the GP without the point is rebuilt before it is used again (the poll rebuilds at its first step, the next round's first search at search_count == 0), and a noisy search estimates from a rebuilt copy. Test: test_search.py::test_last_search_of_a_round_adds_no_point_to_the_gp, which fails at the parent. Fingerprint bfbc6d6737e99d88, unchanged.
