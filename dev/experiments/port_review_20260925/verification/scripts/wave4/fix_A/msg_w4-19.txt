fix: check the sqrt_beta of search_acq_fcn when BADS is created, and a callable's value at each call (W4-19)

acq_fcn_lcb refuses a sqrt_beta that is not None, a callable or a
positive finite real number (W3-10), but only when it is called, at the
first search, after the initial design and the first poll (12
evaluations at D = 3), since BADS did not look at search_acq_fcn. The
value that a callable sqrt_beta returns was not checked: -1 or NaN ran
silently (NaN: fval 0.142 where the default schedule reaches 4e-6), an
array of two values or a string stopped the run with IndexError or
UFuncTypeError. MATLAB's acqLCB.m checks at each call too, accepts any
numeric scalar and a function's value unchecked, and its callers catch
its error.

The rule becomes check_sqrt_beta in acq_fcn_lcb.py, which acq_fcn_lcb
applies at each call, with its message unchanged, and
BADS._init_optim_state_ applies to search_acq_fcn[1], beside the checks
of the other options, so that a wrong value is refused before any
evaluation. acq_fcn_lcb refuses, with ValueError, a callable's value that
is not a positive finite real number, and names the t and n_vars of the
call. The docstring of acq_fcn_lcb and the description of search_acq_fcn
say so.
