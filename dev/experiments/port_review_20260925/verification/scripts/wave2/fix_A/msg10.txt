fix: non_box_cons must return one violation per row, of shape (N,) or (N, 1), or BADS says so when created (W2-10)

The check of non_box_cons's output in _bounds_check_, called on [plb; pub], refused only a 1-D output of other than two elements (`y.shape[0] != 2 and y.ndim == 1`, weakened from MATLAB's test in 8e59038): a scalar or a bool gave AttributeError, a (2, 2) output passed and failed at the start point with "truth value of an array ... is ambiguous", and a constraint that raised on a 2-D input raised its own error. MATLAB BADS calls the constraint on [PLB; PUB] inside a try/catch and requires a 2 x 1 output, or raises an error that states the contract (private/setupvars.m:11-25). The check now does the same for Python's shapes: an array of shape (2,) or (2, 1) passes, anything else, or an exception from the constraint (chained), raises bads:NONBCON with the contract: an N x D array in, one point per row, N violations out, of shape (N,) or (N, 1), true or positive where a point violates the constraints. An (N, 1) output passed the old check too but failed at the first search or poll, since contraints_check indexed the candidates with it; contraints_check now flattens the output, which leaves an (N,) output as it was. The docstring of BADS states the contract, and its example, `lambda x: np.sum(x.^2,1)>1`, MATLAB syntax, is written in Python.
