fix: a random start that violates non_box_cons is drawn again, up to 1000 draws, before BADS refuses it (W2-11)

With x0 missing or not finite, BADS draws the start uniformly in the transformed plausible box, as MATLAB BADS does (private/setupvars.m:83-85), and with non_box_cons given it refused a draw that violated the constraints: with sum(x**2) > 1 on the plausible box [-1, 1]^2, construction failed for 4 seeds of 20 (8, 10, 12 and 13, the B1 verifier's v_inputs.py), about the 1 - pi/4 of the box outside the disc. MATLAB BADS refuses such a start too (private/evalinitmesh.m:22-26), a shared defect. By the PI's ruling, a start that violates the constraints is now drawn again from self.rng in the same box, up to 1000 draws in all, and only then refused with the error of before. The first draw is the same call as before, and a feasible one ends the loop, so a run whose first draw is feasible, and every run with x0 given or without non_box_cons, draws exactly what it drew before. The refusal of a start that violates the constraints once put on the search grid (_init_optim_state_) is left as it is. The docstring of BADS says so at x0.

test_random_x0_is_drawn_again_until_feasible (test_bads_inputs.py): with the disc constraint and seed 8, whose first draw falls outside the disc, BADS constructs, and its x0 is the first feasible draw of the generator (at the parent: "ValueError: Initial starting point X0 does not satisfy non-bound constraints"); with seed 1, whose first draw is feasible, x0 is that draw, as before, and the generator is where one draw leaves it. test_random_x0_that_stays_infeasible_is_refused: a constraint violated everywhere is still refused, after the 1000 draws. Seeds 0 to 19 on the disc all construct now, with the first draw kept for all but 8, 10, 12 and 13. The benchmark gives x0 or no non_box_cons: fingerprint 91f947f78e1087c2, that of the parent.
