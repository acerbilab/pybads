## W1-13: `573ff5a` fix: a GP fit whose every try fails returns its best start with exit flag -1 (W1-13)

- **Test:** `test_robust_fit_every_try_failed_returns_best_start` (`noise_nudge=[0, 0]`, a fit that always raises). It checks that the start clipped back into its bounds wins, and that when its log posterior raises, the other start wins.

- **Fingerprint:** bfbc6d6737e99d88, unchanged.

## W1-12: `9d9ec1e` fix: a failed GP fit raises the noise's lower bound by noise_nudge[1] per failure, as MATLAB BADS (W1-12)
- **Change, as ruled:**
  - The noise's lower bound is taken from `gp.get_bounds()` (the bound at entry) plus `(i_try + 1) * nudge[1]`. At the default `[1, 0]` it no longer moves.
  - The start keeps its cumulative `nudge[0]`.
  - A one-element nudge, or a plain number, is completed as `[n, 0.5 n]`, as MATLAB does. The old code built a 2x1 array with `vstack`.
- **Change beyond the ruling:** the retry's start is clipped into `tmp_gp`'s bounds, as `gpHyperOptimize.m:167` does.
  - Why: with the bound held still, the start's noise rises by 1 per failure and passes the upper bound 5. `SliceSampler` then refuses it with the same "outside the bounds" error as N1.
  - Evidence (Rosenbrock, D = 3, 150 evaluations, `use_slice_sampler` and `double_refit`, seeds 0-2): without the clip, 1 of 3 runs stopped at this commit and 3 of 3 once W1-14 was added. With the clip, 0 of 3. The base had 0 of 3.
  - gpyreg's fit already clips its starts (`f_min_fill`), so at default the clip changes nothing: the fingerprint is the same with and without it at both W1-12 and W1-16.
  - It is a separate hunk you can drop.
- **Tests:**
  - `test_robust_fit_noise_nudge[default|one_element]`: the bound and the start of the noise at each of 7 tries.
  - `test_robust_fit_slice_sampler_starts_within_bounds`: 9 failures with the slice sampler, from a start whose noise sits at its upper bound.
  - At the parent: both nudge cases fail with `ValueError: Lower bound above upper bound for the hyperparameter(s) noise_log_scale.`, and the slice test with `ValueError: The initial starting point X0 is outside the bounds.`
  - Without the clip, the slice test fails with that same message.
  - At the commit: all pass.
- **Fingerprint:** 3a1c15091c801614.
- **Changelog:** "After each failed fit of the Gaussian process, the lower bound of its noise rose by 1, 2, 3, … (by 15 after five failures), and the fifth failure stopped the run with `ValueError`; with `use_slice_sampler=True`, the third did. As in MATLAB BADS, the bound now rises by `noise_nudge[1]` per failure, which is not at all at the default `[1, 0]`, and the retry's start is kept inside the bounds. Results change at default options."

## Noticed outside my rows (not fixed)
- **Retry start with two starts:** with a second fit (`hyp_gp` has 2 rows), the retry averages only with the last row and continues with that single start, so the previous hyperparameters are dropped. MATLAB retries each start separately, each averaged with itself.
- **Warning after a recovered fit:** with `gp_warnings` (off by default), "Failed optimization… after 10 attempts" is still logged when a fit succeeds after retries. MATLAB warns only when a start failed every try.
- **Other prior families:** `_get_random_samples_from_priors_` draws only `"gaussian"` blocks. Other families keep their value, and NaN coordinates inside a Gaussian block are drawn as NaN; MATLAB keeps a hyperparameter that has no prior.
- **Large `noise_nudge[1]`:** a user value such as `[1, 2]` still lifts the bound above 5 after 7 failures, and `set_bounds` raises `ValueError`.
- **Scalar `s2`:** with a scalar `s2_train`, the removal step calls `s2.size`, which fails on a Python float.
- **Test fixture moves with the code:** `refit_case` runs code under test, so its GP changes with each commit. The tests are written so that they do not depend on its exact values.
