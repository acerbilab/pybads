## W1-8

**Files:**

**What changed and why:**
- `_is_gp_refit_time_(alpha, refit_allowed=True)` takes a new argument. With `refit_allowed` false, no refit is due and none is recorded: `lastfitgp` is not set and the GP statistics are not reset. The calibration check still runs.

**Proposed changelog line:** "**Refits without poll training.** With `poll_training=False`, a poll after the first iteration skipped a refit of the Gaussian process's hyperparameters that was due, but counted it as made, which delayed the next refit in the search (MATLAB BADS does the same). The poll now leaves that refit to the search. Results change only with `poll_training=False`."

**Uncertain, for your decision:**
- **The poll's reliability flag changes too.** When the poll declines a due refit, it now gets the calibration verdict on the statistics it keeps. Before, it got `do_gp_calibration = False` for that iteration, as in MATLAB, where `IsRefitTime` sets `unrelgp_flag = 0` when it records a refit. Later poll iterations then saw empty statistics, which count as unreliable. I took resetting the flag to be part of recording the refit. Keeping the old `False` would take extra code to imitate a refit that did not happen. This changes when the poll stops (`_is_poll_stop_`), but only with `poll_training=False`.
- **Where the test lives.** No test file covers the poll step as such, so I put the test in `test_gp_update_failures.py`, next to `test_poll_refit_gives_way_to_poll_training`. That module's docstring is about failed GP updates.
- **No population comparison was run.** The ledger's gate column said a change needs a population comparison with `poll_training=False`; the ruling asks only for a unit test and the fingerprint.
