## W2-17: `07a62ec` fix: the noise test's threshold tol_noise is sqrt(eps) * tol_fun, as in MATLAB BADS (W2-17)
- **Files:** `pybads/bads/option_configs/advanced_bads_options.ini`, `pybads/testing/bads/test_run_control.py`.
- **What changed:** `tol_noise = np.sqrt(np.spacing(1.0)) * self.get("tol_fun")`, which is 1.5e-11, where it was `eps·tol_fun`, 2.2e-19 (MATLAB `bads.m:195`). The typo "variabitility" is corrected. The user's `tol_fun` is still the one read.

  - `[noise_sd_1e-6]` uses noise of SD 1e-6 and stays at level 1 on both sides.
- **Fingerprint:** unchanged.
- **Changelog, Fixed:** "**Noise test.** When `uncertainty_handling` is left empty, a target is taken as noisy when two evaluations at the starting point differ by more than `tol_noise`, now `sqrt(eps) * tol_fun` (1.5e-11 at default) as in MATLAB BADS. 1.1.0 used `eps * tol_fun` (2.2e-19), so that a deterministic target whose value changes in its last digits from call to call, for example a sum taken in varying order, was optimized as a noisy one, with more evaluations and a worse result."
- **Upgrading from:** "A target whose two evaluations at the starting point differ by at most `sqrt(eps) * tol_fun` is optimized as deterministic when `uncertainty_handling` is left empty, without the final samples of a noisy run."

## W2-19: `4c823cb` fix: a user option of None stands for its default, and the boolean options take only booleans (W2-19)
- **Files:** `pybads/bads/options.py`, `pybads/bads/bads.py` (4 lines after `validate_option_names`), `pybads/testing/bads/test_options.py`.
- **What changed:**
  - **(i) `None` stands for the default.** `Options.__init__` leaves a user value of `None` unset and out of `useroptions`, so the default holds. Its name goes into a new attribute, `unset_user_options`, documented in the class docstring. `validate_option_names` also checks those names, so a misspelt name given `None` is still refused.
  - **(ii) Boolean options take only booleans.** The new `Options.validate_boolean_options(options_paths, extra_names, excluded_names)` refuses any user value that is not a `bool` or `np.bool_` with `ValueError("options['<name>'] needs to be True or False, not '<value>'.")`. The boolean options are those whose default text in the files is `True` or `False` (45 of them), plus `uncertainty_handling`. `'on'` and `'off'` are not converted.
- **Uncertain: `plot` is left out of the check.** Its default is `False`, but its description lists `"profile"` and `"scatter"`, and it is read only by a branch that does nothing (KD-B1-5 (e)). Refusing those strings would contradict the documentation. `test_plot_takes_the_names_of_plots` pins this. If the PI prefers the literal rule, the fix is to remove `excluded_names=("plot",)` and change `plot`'s description.
- **Tests:**
  - `test_none_stands_for_the_default`: `nonlinear_scaling=None` keeps the log transform. At the parent: `assert None is True`.
  - `test_none_budget_is_the_default_budget`: `max_fun_evals=None` gives 500·D, and a run with `max_iter=3` works. At the parent: `ValueError: options['max_fun_evals'] needs to be a positive integer, not None.`
  - `test_boolean_options_refuse_other_values` with `"off"`, `"on"`, 0 and 1, for both `uncertainty_handling` and `nonlinear_scaling`: `DID NOT RAISE` at the parent (×8).
  - `test_boolean_options_take_booleans` (True, False, np.True_, np.False_), `test_none_for_an_unknown_option_is_refused` and `test_plot_takes_the_names_of_plots` are guards.
- **Fingerprint:** unchanged.
- **Changelog, Changed:** "**`None` and boolean options.** A user value of `None` stands for the option's default, as an empty value does in MATLAB BADS; 1.1.0 used `None` itself, so that `nonlinear_scaling=None` turned the log transform off, and a numeric option of `None` stopped the run. The options whose default is `True` or `False`, and `uncertainty_handling`, take only `True` or `False` (NumPy booleans included): `BADS` raises `ValueError` for any other value. 1.1.0 read any value as true or false by Python's rules, so that MATLAB's `\"off\"` was true."
- **Upgrading from:**
  - "The options whose default is `True` or `False`, and `uncertainty_handling`, take only booleans: `BADS` raises `ValueError` for `0`, `1`, `\"on\"`, `\"off\"` or any other value."
  - Optionally: "A user value of `None` stands for the default: with `nonlinear_scaling=None`, variables are log-transformed as at default."

## W2-15: `55cc349` fix: the display option follows MATLAB BADS's display levels, "notify" and "final" included (W2-15)
- **Files:** `pybads/bads/bads.py`, `pybads/bads/option_configs/basic_bads_options.ini` (the `display` description names `"full"`), `pybads/testing/bads/test_bads_logger.py`.

- **Fingerprint:** unchanged.
- **Changelog, Fixed:** "**Display levels.** `display` takes MATLAB BADS's levels, read from its first three letters in any case: `\"notify\"` shows the opening message and the warnings, `\"final\"` also the final message, `\"iter\"` (or `\"all\"`) also the iteration lines, `\"off\"` (or `\"none\"`) only the warnings, and `\"full\"`, PyBADS's own, the debug messages too. 1.1.0 showed everything for any value but `\"off\"` and `\"full\"`, including `\"notify\"` and `\"final\"`.
